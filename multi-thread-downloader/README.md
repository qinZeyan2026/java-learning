# Java 多线程模拟下载器 (Multi-thread Downloader)

## 1. 项目简介
本项目是一个基于 Java 实现的多线程分块下载模拟器。不依赖真实网络，通过内置 `RemoteFile` 模拟网络延迟与远程文件服务。程序将目标文件切分为若干数据块，借助线程池并发拉取各块数据，使用 `RandomAccessFile` 对本地文件的指定偏移位置写入数据，下载完成后自动校验本地文件与源文件的一致性。

项目目的：对比单线程下载与多线程并发下载的性能差异，理解 IO 密集型场景下多线程的收益与并发安全问题。

## 2. 核心知识点
- **多线程基础**：`Thread`、`Runnable`、`CountDownLatch`，用于等待全部下载任务完成
- **并发安全**：`synchronized` 保护共享 `RandomAccessFile`；`AtomicInteger` 原子类实现无锁进度统计
- **线程池**：手动构造 `ThreadPoolExecutor`，熟悉七大参数、线程工厂、拒绝策略
- **随机IO**：`RandomAccessFile.seek()` 定位文件偏移，支持多线程分块写入同一个文件
- **健壮性设计**：参数合法性校验、分块失败自动重试、旧文件清理，规避脏数据

## 3. 功能列表
- 单线程顺序下载，作为性能基线（baseline）
- 多线程分块并发下载，可自定义线程数量
- 分块读取失败重试机制，模拟网络抖动
- 实时统计已下载字节数
- 下载完成后文件完整性校验
- 批量性能实验，自动输出多组耗时数据

## 4. 性能测试数据（对照组实验）
**测试环境**：24核CPU，文件大小50MB，模拟带宽5MB/s，单线程理论耗时约10s

### 4.1 单线程 vs 8线程多线程
| 版本 | 第1次 | 第2次 | 第3次 | 平均耗时 |
| :--- | :--- | :--- | :--- | :--- |
| 单线程 | 10537 ms | 10626 ms | 10554 ms | **10572 ms** |
| 多线程 (8) | 1496 ms | 1480 ms | 1464 ms | **1480 ms** |

**结论**：8线程加速比约 **7.14倍**。受锁竞争、线程调度开销影响，没有达到理论8倍加速，但性能提升明显。

### 4.2 线程数扫描测试（块大小固定1MB）
| 线程数 | 第1次 | 第2次 | 第3次 | 平均耗时 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | 10564 | 10618 | 10600 | 10594 ms |
| 2 | 5281 | 5275 | 5290 | 5282 ms |
| 4 | 2714 | 2770 | 2731 | 2738 ms |
| 8 | 1474 | 1493 | 1465 | 1477 ms |
| 16 | 848 | 840 | 857 | 848 ms |
| 32 | 449 | 452 | 444 | 448 ms |

**结论**：本任务属于 **IO密集型任务**（大量模拟网络等待，CPU空闲），增加线程数可以持续获得加速效果。如果是CPU密集型计算任务，线程数超过CPU核心数后，上下文切换开销会反超收益，性能下降。

## 6. 踩坑与排错记录
1. **共享 RandomAccessFile 并发错乱**
   多个线程共用同一个 `raf` 对象，`seek()` 和 `write()` 不是原子操作。线程交错执行会造成写偏移错乱、文件内容损坏。
   ✅ 解决：把 `seek + write` 包裹在 `synchronized (raf)` 同步块内。

2. **CountDownLatch 重复 countDown**
   `finally { latch.countDown() }` 写在重试循环内部，一次任务重试多次就会多次减计数，主线程提前结束，校验时文件还没写完。
   ✅ 解决：try-finally 放到 while 重试循环外层，保证一个任务只会 countDown 一次。

3. **旧文件残留污染校验结果**
   `RandomAccessFile` 以读写模式打开已有文件时，不会清空原有内容；新文件比旧文件短的情况下，尾部残留旧字节，校验失败。
   ✅ 解决：每次开始下载前，先删除本地旧文件。

## 7. 运行方式
1. 环境要求：JDK 8 及以上
2. IDEA / Maven 导入项目
3. 直接运行 `com.example.downloader.Experiment`，自动执行批量性能测试，控制台输出表格数据

## 8. 不足与改进方向
- 当前重试是固定间隔等待，可以改成指数退避策略
- 进度打印只统计总字节，没有实时进度条
- 缺少暂停、断点续传功能
- 没有限制并发带宽
